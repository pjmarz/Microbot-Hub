# Agent Server Plugin Config

The `[M] Agent Server` plugin's config UI exposes these knobs. Locked-in values for this repo's tooling:

| Setting | Value | Rationale |
|---|---|---|
| **Port** | `8081` | Default. All our tooling assumes this port. Change here = change in `HEALTHCHECK.md`, `dashboard/app.js`, and any future orchestrator scripts |
| **Max Results** | `200` | Default. Limits how many items `/npcs`, `/objects`, etc. return per query. 200 is more than enough for any one-tile area |
| **Auth token** | (user-set, NOT committed) | See note below |
| **Stealth bind** | `off` | When off, the server binds to `127.0.0.1` (localhost). When on, binds to `0.0.0.0` (LAN-visible). Keep off for local-only use |
| **Bind mode** | `TCP` | Standard HTTP. Don't change |

## Auth (resolved 2026-05-23)

Auth IS required. Phase 0 verification confirmed:

- **Header:** `X-Agent-Token: <token>` (not `Authorization: Bearer ...` despite what some docs imply)
- **Token storage:** `~/.runelite/.agent-token` (one line, hex string, auto-generated by the plugin)
- **Without the header:** every endpoint returns 404 (security through obscurity — looks like a dead port to unauthorized probes)
- **Token rotation:** clearing the Auth token field in the plugin UI triggers regeneration. The plugin warns in the log: `Agent server auth token was cleared; regenerating to keep auth enforced`. Read the file again after any reset.

## Where the token is stored

`~/.runelite/.agent-token` — one hex string, no formatting. Read directly:

```powershell
$TOKEN = Get-Content "$env:USERPROFILE\.runelite\.agent-token"
```

```bash
TOKEN=$(cat ~/.runelite/.agent-token)
```

**Do not commit the token to git.** If a future orchestrator script needs to ship the token via env var, use an untracked local file:

```
tools/agentserver/.env.local       # gitignored, holds AGENT_SERVER_TOKEN=...
```

## Stealth bind: when would you turn it on?

Only if you want to drive the bot from a different machine on your LAN (e.g. orchestrator running on a separate server, dashboard on a tablet). Risks: any device on the LAN can probe the Agent Server. Token becomes critical, not optional.

For this MVP, we keep it `off`. Localhost-only.
