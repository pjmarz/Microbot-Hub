# Agent Server Healthcheck

curl one-liners for diagnosing Agent Server connectivity and endpoint behavior. Run from any shell on the same machine as the Microbot client.

## Prerequisite

The `[M] Agent Server` plugin must be **enabled** (toggle ON / orange) in your Microbot client's plugin list. Just having it installed is not enough.

## Smoke test

```bash
curl -sS http://127.0.0.1:8081/state
```

**Expected:** JSON object with player state (position, world, login status).

**If you see `curl: (7) Failed to connect`:**
- The Agent Server plugin is not enabled. Open the Microbot client, find `[M] Agent Server` in the plugin list, flip the toggle to ON.
- Or the client isn't running.

**If you see HTTP 401:**
- The auth token IS required. See "Auth-token verification" below.

## Endpoint catalog

### Game state

```bash
# Player position, world, login status, animation
curl -sS http://127.0.0.1:8081/state

# All 23 skills with XP + level
curl -sS http://127.0.0.1:8081/skills

# Single skill (case-sensitive: Attack, Mining, Ranged, etc.)
curl -sS "http://127.0.0.1:8081/skills?name=Mining"

# Login screen state (loginIndex, loginError if applicable)
curl -sS http://127.0.0.1:8081/login

# Current inventory contents
curl -sS http://127.0.0.1:8081/inventory

# Nearby NPCs (optional name, distance filters)
curl -sS "http://127.0.0.1:8081/npcs?name=Guard&distance=15"

# Nearby objects (rocks, doors, trees, etc.)
curl -sS "http://127.0.0.1:8081/objects?name=rocks&distance=10"

# Ground items
curl -sS http://127.0.0.1:8081/ground-items

# Bank state (open/closed)
curl -sS http://127.0.0.1:8081/bank

# Current dialogue state
curl -sS http://127.0.0.1:8081/dialogue
```

### Widgets

```bash
# All visible widget interface IDs
curl -sS http://127.0.0.1:8081/widgets/list

# Search widgets by keyword
curl -sS "http://127.0.0.1:8081/widgets/search?text=bank"

# Inspect a specific widget tree
curl -sS "http://127.0.0.1:8081/widgets/describe?id=134"
```

### Script lifecycle

```bash
# List all installed plugins (enabled flag included)
curl -sS http://127.0.0.1:8081/scripts

# Plugin status (runtime, startedAt)
curl -sS "http://127.0.0.1:8081/scripts/status?className=net.runelite.client.plugins.microbot.miningplus.AutoMiningPlusPlugin"

# Start a plugin by name (partial match)
curl -sS -X POST http://127.0.0.1:8081/scripts/start \
    -H "Content-Type: application/json" \
    -d '{"name": "Auto Mining Plus"}'

# Stop a plugin
curl -sS -X POST http://127.0.0.1:8081/scripts/stop \
    -H "Content-Type: application/json" \
    -d '{"name": "Auto Mining Plus"}'
```

## Auth scheme reference

Resolved during Phase 0: `X-Agent-Token: <token>` header. The token lives at `~/.runelite/.agent-token`. Read it from there rather than pasting from the UI (the UI field shows asterisks).

```bash
TOKEN=$(cat ~/.runelite/.agent-token)
curl -H "X-Agent-Token: $TOKEN" http://127.0.0.1:8081/state
```

Without the header (or with the wrong scheme like `Authorization: Bearer`), the server returns 404 on every path — including paths that exist. This is intentional obfuscation, not a routing bug.

## Verified behavior (2026-05-23)

Phase 0 verification complete on Pete's throwaway `itzpjmarz`. Findings:

- **Auth required: YES.** Every endpoint returns 404 (not 401) without a valid token. Security-through-obscurity by design — the server intentionally looks "not there" to unauthenticated probes.
- **Header format: `X-Agent-Token: <token>`** (NOT `Authorization: Bearer ...` as the `docs/AGENT_SERVER.md` doc implies).
- **Token storage**: `~/.runelite/.agent-token` (auto-generated by the plugin; regenerates if the UI's Auth token field is cleared).
- **Stealth bind**: when ON, socket only opens once a script begins running. When OFF (our recommended dev setting), socket always open while plugin enabled.
- **Endpoint count**: 26 endpoints in current plugin version (Hub doc claims 34; some are aspirational).

## Common failure modes

| Symptom | Likely cause | Fix |
|---|---|---|
| `Failed to connect to 127.0.0.1 port 8081` | Plugin disabled or client not running | Enable `[M] Agent Server` plugin (orange toggle) |
| HTTP 404 on every path | Missing or wrong auth header | Add `-H "X-Agent-Token: $TOKEN"` (read token from `~/.runelite/.agent-token`) |
| HTTP 404 on some paths only | Endpoint not in this plugin version (26 of the 34 documented endpoints exist in current Microbot release) | Check `GET /scripts` returns 200 first to confirm auth works; then probe each desired path |
| HTTP 500 | Server-side error (game state unavailable) | Make sure you're logged into the game, then retry |
| Empty / `null` response | Game state not yet populated (just logged in) | Wait a few seconds for client to settle |
| Stale data | Polling too fast OR client paused | The Agent Server reflects game state in real time; if data looks frozen, check whether the bot is paused |
| Token suddenly invalid | Auth token was cleared or regenerated (e.g. plugin Reset) | Re-read `~/.runelite/.agent-token`; the plugin regenerates on clear |

## CORS check (for browser dashboard)

The Phase 1 dashboard runs in a browser opening `index.html` via `file://`. Browsers block cross-origin XHR by default. The Agent Server may or may not set permissive `Access-Control-Allow-Origin` headers.

```bash
# Check CORS headers from the server response:
curl -sS -i http://127.0.0.1:8081/state | grep -i "access-control"
```

If you see `Access-Control-Allow-Origin: *` → dashboard works from `file://` directly.
If you see nothing → use `dashboard/serve.ps1` to serve via `http://localhost:<port>` to dodge the CORS rule.
